## Triage (organized for Sunday review)

### Extraction quality
- **Cloud annotations extracted without their markup_text** — recurring across Office, WC, Bath01, S2 (10:16, 10:17, 10:18). Model emits cloud locations without the associated handwritten content the cloud actually contains.
- **Hallucinated cloud locations** — "red cloud around Office 01W/01S/01E... I don't even see a fucking bubble" (10:15); "I don't see a cloud of shower west. That's inaccurate" (10:17).
- **Misread that changed meaning** — extracted "match style" when actual markup said "spring point + high point should match" (matching elevations, not style) (10:27). High-confidence semantic misread.
- **Missed readable handwritten markups** — manually identified ones the model skipped: "add in low hw/slab" near Office 01 West (10:21), "Add in through middle left area" (10:24), "low H near shower 1 East" (10:26).
- **Vague location refs when multiple targets exist** — "water closet section, which one?" (10:25).
- **"[partially illegible]" prefix is repeated to the point of being noise** — every visible markup leads with it. When the same uncertainty label fires on every row, the label stops carrying signal. Either tighten the threshold for emitting it, or surface it as a per-page banner ("source is low-resolution; many markups marked partially illegible") rather than per-row.

### Rendering pipeline (cross-input pattern — important)
- **PDF rasterization DPI is too low** for both model input and the in-app viewer. Source detail is lost before extraction even starts, so the model is reading a worse version of the PDF than the human user sees. This was also happening on the Bluebeam-style synthetic PDFs but went unnoticed because those start crisp; on a hand-drawn scan it becomes glaring.
- **Implication for extraction quality**: model "[partially illegible]" outputs may be partly a rasterization artifact, not a vision-model ceiling. Raising pdf2pic DPI before re-running case_006 / Design-Redlines-02 would test this.
- **Implication for UX**: even when the model extracts correctly, the user can't visually verify against the in-app rendering because the source is too pixelated to read. Verification loop is broken on hard PDFs.

### Counter calibration
- **30 of 36 markups auto-flagged (83%)** — on this PDF probably honest behavior (input genuinely is mostly illegible), but at this rate the "FLAGGED" filter carries no useful information for the drafter. Consider: progressive flag levels (low/medium/high uncertainty) so flagged ≠ binary, or surface the flag-rate as a per-job quality signal ("83% flagged — consider re-uploading at higher resolution").

### UX/workflow
- **Flag state ambiguous, inverted intent** — "Oh that's wild. These are all flagged. I was unflagging them." (10:19). High-confidence UX bug.
- **No comment/clarification reply path** — "I can't even write any comments" (10:20); "typing 'what' and 'what's' is ambiguous here" (10:20).
- **No SSE progress per-page** — "extracting is a little frozen right now so 0% markups will appear as pages are analyzed" (10:14). Progress only visible at completion.
